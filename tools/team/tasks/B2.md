# B2: First-run Set up your business, and the Finish setup card (DEV-B)

Goal: Doc 4 F2 (and the Doc 1 rule L1 adds for it). After installing, the father is guided to everything the app needs before the first bill, without hunting through Settings.
Branch: feat/android-first-run-setup from origin/main, after B1 and L1 are merged.
Allowed paths: ui/lock (the step after PIN setup), a new ui/setup/ package, ui/worker/HomeScreen.kt and HomeViewModel.kt (the card only), domain/setup/ (new, pure rules), the use cases that already save Settings (reuse, do not duplicate), tests, docs/DECISIONS.md, docs/QUESTIONS.md.
New dependency: none. No schema change.

Behaviour:
1. Right after the first PIN is set (first run only), show "Set up your business": business name (pre-filled from the seed), owner name, address (up to 4 lines), phone, bill footer. Same limits as Settings (Doc 2 / DECISIONS.md). Buttons: "Save and continue" and "Skip for now". Saving goes through the existing Settings use cases (change log as today).
2. Sales Home shows a "Finish setup" card while anything is missing. Items, each one tappable and opening the right Admin screen:
   - "Business details" while owner name, address or phone is empty (the bill shows placeholders until then);
   - "Prices" while any product lacks a default price for any customer type, with the count missing ("Prices: 3 missing").
   The card disappears when nothing is missing. It never blocks anything. It carries no money amounts and no cost data.
3. A pure function setupGaps(settings, products, customerTypes, prices) decides the items. Tests cover: fresh install, all done, only prices missing, a product added later (the card comes back), a skipped setup screen.
4. The debug demo flow must still work (demo data has prices, so no card).
Tests first; mutation proofs: the card shown when nothing is missing; a missing price not counted; the setup screen shown on a second run.
Evidence: screenshots (fresh install: PIN, setup screen, Home with card; after setup: Home without card) at 360 dp, font 1.3, in out\B2\.
Out of scope: entering prices inside the setup screen, any new setting, any change to the bill.
