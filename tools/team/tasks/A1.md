# A1: Printer auto-detect, ESC/POS, Printer check screen (DEV-A)

Goal: Doc 4 s1 F3 and F4, and Doc 4 s5. The first bill prints with no setup on most built-in-printer handhelds. Everything here is testable without the real device. The device check is task A2.
Branch: feat/android-print-autodetect from origin/main.
Allowed paths: android/app/src/main/java/com/mamre/billing/print/**, a new android/app/src/main/aidl/** (vendor AIDL only), the Printer check screen and its route under ui/admin/ (one new file, plus one row in Settings and one route line), android/app/src/main/AndroidManifest.xml (permissions and <queries> only), android/app/src/debug/AndroidManifest.xml, the release manifest rules in android/buildSrc (allowlist update only), the matching tests, docs/DECISIONS.md, docs/QUESTIONS.md.
New dependency: none.

Read first: Doc 1 s5 (bills, reprint, print failure), Doc 2 s7 (printing), Doc 4 s5, the existing print/ package (ReceiptBuilders, the current ReceiptPrinter or mock printer, PrintFailureKeepsBillTest).

Build:
1. A PrinterDriver interface: name, isAvailable(context), print(lines: the 32-column receipt) -> success or failure with a reason. The existing receipt builders stay the only source of the text.
2. Drivers, tried in this order by a pure PrinterChain:
   a. VendorServiceDriver for the Sunmi built-in service (package woyou.aidlservice.jiuiv5, interface IWoyouService, bound through its public AIDL; only if the package is installed). Structure it so A3 can add more vendors as one class each.
   b. BluetoothEscPosDriver: among already-paired devices, pick the built-in printer (name matches InnerPrinter, Printer, POS, PT- or MPT, or device class imaging/printer; if exactly one paired device is a printer, take it). Connect RFCOMM with the serial profile UUID 00001101-0000-1000-8000-00805F9B34FB. Send ESC/POS: ESC @, header lines bold and centred, body left aligned, line feeds at the end. Text is ASCII; characters outside ASCII become '?'.
   c. AndroidPrintDriver: PrintManager with a PrintDocumentAdapter that draws the same 32 lines in a monospace font on a 58 mm page (48 mm printable). It opens the system dialog, so it is last.
3. Auto-select: at the first print, run the chain; save the first working driver's name in the setting printer_method (settings table; no schema change). Later prints use it. If it fails, run the chain once more and save the new winner. If all fail, the bill stays saved and the screen shows exactly: "Printer not ready. The bill is saved. Tap Reprint." (AT-11). No settings screen to fill in.
4. Bluetooth permission (Android 12+): BLUETOOTH_CONNECT is asked at the first print that needs it, with this sentence before the system prompt: "Mamre needs permission to reach the built-in printer." If denied, the chain moves to the next driver. Manifest: BLUETOOTH_CONNECT; BLUETOOTH with maxSdkVersion 30; a <queries> block naming the known printer packages. The debug manifest may add QUERY_ALL_PACKAGES for the Printer check report; the release manifest must not.
5. Update the release manifest rules in buildSrc so these permissions are allowed and INTERNET, storage permissions and QUERY_ALL_PACKAGES stay forbidden in release. Unit tests for the rules.
6. Printer check (Admin > Settings > Printer check, both builds): shows manufacturer, brand, model, device, Android version and SDK level, paired Bluetooth devices (name, class), print services, installed packages whose name contains print, printer, pos, sunmi, imin, telpo, urovo, senraise, ciontek or iposprinter (release: only what <queries> allows), and the result of each driver's isAvailable. Buttons: "Print test page" (runs the chain, prints these details and one golden bill) and "Share report" (share sheet, plain text). Text only, no network.

Tests first:
- PrinterChain: order, first success wins and is saved, a saved driver is used first, failure then re-run, all fail -> bill kept and the message, permission denied -> next driver. Use fake drivers.
- ESC/POS bytes: golden byte files for the four golden bills of AT-5 (corporate, normal credit, cash walk-in, payment receipt). Exact bytes.
- Bluetooth device picking from fake paired lists (one printer, several devices, none, a printer by class only).
- AndroidPrintDriver page layout: 32 columns fit 48 mm at the chosen font size (pure calculation test).
- Release manifest rules: allowed and forbidden permissions.
Mutation proofs: the chain ignores the saved driver; a failed print loses the bill; the bold command missing from the header bytes; QUERY_ALL_PACKAGES allowed in release.
Evidence: tests and counts, mutations, screenshots of Printer check on the emulator (360 dp, font 1.3) in out\A1\, the debug APK copied to C:\dev\mamre-team\out\A1\mamre-debug.apk for task A2.
Out of scope: vendor SDK jars, any cloud printing, printer settings screens, changes to the receipt text.
